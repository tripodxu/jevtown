# agent/RELAY · 多 agent 接力协议

> 适用场景：一个任务跨多个 agent（或跨会话）**串行**完成——A 做一半交给 B，B 交给 C。
> 目标：**接棒 agent 不重新全量阅读项目**，靠交接记录在 5 分钟内恢复上下文。

## 什么时候必须写交接

- 任务未完成但当前 agent 要停（上下文将满、需要人工决策、等待外部结果）。
- 任务跨会话继续（下一次由新 agent 接手）。
- 执行中发现任务需要换人（卡描述错误、需要其他专长）。

## 交接放在哪

- 进行中的任务：任务卡同目录留 `<任务id>-handoff.md`（从
  [templates/handoff.md](templates/handoff.md) 复制），**最新状态置顶**。
- 任务完成：交接内容压缩成一条进 [MEMORY.md](../MEMORY.md)（同样最新置顶），
  然后删除临时 handoff 文件，避免仓库堆积半成品状态。

## 交接记录规范（handoff.md）

固定六段，**最新在上**（多轮接力时新段落插到旧段落上方，旧的保留可追溯）：

1. **当前状态**：任务卡 id / 目标 / 整体完成度（百分比或"第 3/5 步"）。
2. **已完成**：具体到文件与行为，附验证证据（命令 + 结果）。
3. **未完成 / 下一步**：按优先级排序，写清"从哪里继续"（文件:行号 级别）。
4. **坑与决策**：本任务做过的取舍、试过不通的路、临时 hack（含原因）。
5. **待确认问题**：需要主控或用户拍板的事项（没有就写"无"）。
6. **环境状态**：分支名、本地是否留未提交改动、是否需要真实 key 的步骤。

## 接棒 agent 的标准动作（≤5 分钟恢复上下文）

```
1. 读根 AGENTS.md（L0）                         ~1 分钟
2. 读该任务最新的 handoff.md（置顶那段）          ~2 分钟
3. 按 handoff 的"下一步"只读涉及的文件/文档      ~2 分钟
4. 动手前：确认 handoff 的"环境状态"与当前 git 一致（分支、有无未提交改动）
```

禁止：接棒后先通读仓库、先重跑全量测试再读交接（测试何时跑由任务卡验收标准决定）。

## 接力中的提交

- 每个执行 agent 完成**一个可验收子目标**就提交一次，信息里引用任务卡 id。
- 不许把"半成品 + 交接说明"留在未提交状态过夜；未完成可以提交（分支隔离），
  但必须在提交信息或 handoff 里说清完成度。

## 质量门（接力不掉链子）

- 接棒 agent 动手前必须能回答：目标是什么、做到哪一步、下一步第一个动作是什么。
  答不上来 = 交接记录不合格，退回给上一棒补写，不猜着做。
- 每个子目标的自测证据写进 handoff；主控合并前按任务卡验收标准逐条核对。
