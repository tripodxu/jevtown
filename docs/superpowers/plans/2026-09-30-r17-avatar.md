# R17 · 创意轮：程序化人格头像——一万个居民各有一张确定性的"脸"

> 轮换位置：R16 优化 ⇒ **R17 创意** ⇒ R18 前端。writing-plans 规范，inline 执行。

**Goal:** 人格声音卡片与地图悬停档案获得程序生成的头像：`hash32(pool, id)` 驱动的
5×5 **镜像**徽章（经典 identicon 算法——左 3 列生成、右 2 列镜像，天然对称才像"脸"）。
同一 id 永远同一张脸（与引擎同一确定性纪律）；零新增调用、零图片资产。

**Architecture:** 新文件 `public/avatar.js`（render.js 与 grid.js 共用；不放进 shared/
——头像纯属前端表现，三端不需要）。颜色**只取主题令牌**：格子 = `--accent` 的
hash 决定浓淡（opacity 0.35–0.89），底 = `--card-2`——四主题自动跟随，不引入任何新色。
每格画不画、浓淡由 LCG 位流决定（seed = hash32('avatar', pool, id)，rng.js 既有工具）。

## 改动

1. 新增 `public/avatar.js`：`avatarSvg(pool, id, { size })` → 内联 SVG 字符串。
2. `render.js` voicesView：卡片改 flex（头像 + 文案列）；pool 用 `result.post.pool`
   ——**API base.post 补 `pool` 字段**（加法契约变更，Worker 与 replay.js 两处同步，记 MEMORY）。
3. `grid.js` attachTooltip：tooltip 首行加 32px 头像（与人格档案同源）。
4. `styles.css`：`.voice` flex 布局 + `.avatar` 圆角。
5. 测试 `test/avatar.test.js`（纯函数，Node 可测）：同一 id 同一 SVG（确定性）、
   不同 id 大概率不同脸、rect 数量在合理区间、镜像对称（生成逻辑自查：列 x 与 4-x 成对出现）。
