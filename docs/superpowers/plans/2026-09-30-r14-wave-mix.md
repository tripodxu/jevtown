# R14 · 创意轮：每波反应构成——把"传播稀释"画出来

> 轮换位置：R13 优化 ⇒ **R14 创意** ⇒ R15 前端。writing-plans 规范，inline 执行。

**Goal:** 报告的波次段只有"每波多少人 + 情绪均值"，看不见**构成**：第 1 波的 600 人里
多少停下/乐见，第 2 波涌进来的 1,500 人是不是大多中性划走。用 R8 已有的两份逐人字节
（`reach` 波次 × `looks` 反应）做交叉表，一波一根**堆叠条**（LOOKS 反应色——这里语义
正确，因为它就是"什么反应"的类别色），传播稀释一眼可见。零 Worker 改动、零新增调用。

**Architecture:** `summary.js` 纯函数 `waveMix(presetId, keys, looks, reach)` →
`charts.js` 的 `waveMixChart()`（DOM 堆叠条，复用 `.seg` 家族的令牌与等宽数字）→
`render.js` 接在波次漏斗之后。旧存档无 `reach` → 段落优雅缺席（与传播层同规则）。

## 改动

1. `summary.js` 新增 `waveMix(presetId, keys, looks, reach)`：
   `{ waves: [{ wave, size, mix: [{ reaction, zh, count, share }] }] }`——只数到达过的人
   （reach 字节 ≥ 1），按波次 × 反应交叉计数，反应按次数降序（各波同序，便于跨波对比）。
2. `charts.js` 新增 `waveMixChart(mix, { width })`：每波一行——`第 N 波 · size 人` 标签 +
   一根堆叠条（段色 = `LOOKS[lookOf(...)]`，段宽 = share，最小 2px）+ 段内/悬停计数
   （`<span title>` 承载）。
3. `render.js` 新增 `waveMixView(result)`：`result.reach` 存在才渲染，接在 `wavesView` 后。
4. 测试（`test/summary.test.js` +2）：交叉计数正确（Σ段 = 波大小、Σ波 = 判定数）；
   各波 mix 的反应序一致（主序按全城次数）。
