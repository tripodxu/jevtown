# R23 · 创意轮：小镇快报——报告顶部的三行式 TL;DR

> 轮换位置：R22 优化 ⇒ **R23 创意** ⇒ R24 前端。writing-plans 规范，inline 执行。
> 前提：模型不写一个字——快报的每句话都是**固定模板 + 真实数字**的拼装（labels 单源），
> 这与项目前提一致：拼装逻辑可测，措辞可审。

**Goal:** 报告开头一段 2-4 行的快报，回答"这次检查到底怎么样"：
传播句（几波/多少人/在哪收住）→ 态度句（乐见/反感/停下的百分比）→
条件句（最买账的群体 / 反感最集中的群体，来自 segments 的显著提升名单）。

**防病句设计（R5 的教训）：** 句式全部用**名词短语 + 冒号注记**（`最买账：跑步骑行
（兴趣 · 52% · 1.8×全城）`），不用需要主谓宾搭配的从句；分支只有三处（波数 1/多/0），
每支的模板都独立成句。选择逻辑进 `summary.js` 纯函数（可测），措辞进 `render.js`
（labels 消费方），两分离。

## 改动

1. `summary.js` 新增 `reportBrief(counters, waves, segments, terrain)`：
   `{ waves, reach, gladPct, sorryPct, stoppedPct, best, worst }`——best/worst 取自
   `topSegments`（lift ≥ 1.3 且 ≥8 人的既有门），无显著群体时为 null。
2. `render.js` `briefView(result)`：报告最前（source-text 之前）渲染 `.brief` 盒，
   波数=1 与 >1 各一套模板；best/worst 用名词短语注记式。
3. `styles.css`：`.brief`（inset 底 + 快报行，em 高亮沿用 terrain-say 的笔触）。
4. 测试（`test/summary.test.js` +3）：单波/多波分支；best/worst 选择与 null 分支。
